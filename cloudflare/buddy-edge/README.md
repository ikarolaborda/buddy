# buddy-edge

Cloudflare Worker package for the Buddy edge pilot described in
`docs/plans/2026-09-15-cloudflare-buddy-usability-performance.md` (sections 5-8, 10-12, 15).

It gives one task a read-only live dashboard, projects Azure-published task events into a Durable Object per
client and task, supervises task health with a bounded Workflow, caches immutable artifact summaries in KV
behind fresh authorization, and holds a fully gated browser diagnostics path. Azure remains the source of
truth for every task; this Worker never writes task state.

## What is here

| Path | Role |
| --- | --- |
| `src/index.ts` | Entrypoint: `fetch` router and `queue` consumer, exports the Durable Objects and the Workflow |
| `src/router.ts` | Routes, security headers, session cookies, WebSocket hand-off |
| `src/do/task-progress.ts` | `BuddyTaskProgress`: per-task projection, replay buffer (100 events / 24 h), tickets, hibernating sockets |
| `src/do/edge-budget.ts` | `BuddyEdgeBudget`: per-UTC-day counters, 80% warning, 100% denial, reconciliation items, capture slots |
| `src/consumers/events.ts` | Queue consumer: validate, project, ack only after acceptance, retry with backoff, supervisor creation |
| `src/consumers/artifacts.ts` | Same consumer for the isolated artifacts queue |
| `src/workflows/decision.ts` | Pure supervisor decision table (unit-tested without the Workflow runtime) |
| `src/workflows/supervisor.ts` | `BuddyTaskSupervisor` Workflow: delegate, wait for terminal event, authoritative reads, diagnose, one recovery |
| `src/cache.ts` | KV summary cache with authorization first (`summary:v1:<client>:<artifact>:<hash>:<processor>`) |
| `src/captures.ts`, `src/captures/*` | Browser diagnostics: policy enforced before navigation, `CaptureRunner` interface, puppeteer runner, mock runner |
| `src/azure.ts` | Client for the `/api/internal/cloudflare/*` contract (`X-Buddy-Edge-Key`, `X-Buddy-Edge-Session`) |
| `src/ingest.ts` | `POST /internal/events`: Azure publishes envelopes through the Worker instead of the Queues REST API |
| `src/objects.ts` | Signed upload/download tokens (`bup1`/`bdl1`), the public `/uploads` and `/downloads` routes, and the internal R2 object API |
| `public/` | Single-task dashboard (plain HTML/CSS/JS, no inline handlers, no external assets) |
| `test/` | Vitest suites that run inside the Workers runtime |
| `wrangler.jsonc` | Two environments: `preview` (`buddy-edge-preview`) and `production` (`buddy-edge-prod`) |

Node 22.12+ (Node 24 is used for development). Versions are pinned exactly in `package.json` and locked in
`package-lock.json`: wrangler 4.131.2, typescript 7.0.2, vitest 4.1.11, @cloudflare/vitest-plugin 1.1.9,
@cloudflare/workers-types 5.20260915.1, @cloudflare/puppeteer 1.4.0.

### Why `@cloudflare/vitest-plugin`

`@cloudflare/vitest-pool-workers` (last 0.22.0, August 2026) has been superseded by `@cloudflare/vitest-plugin`
(1.1.9 at the time of writing), which is the currently maintained Workers Vitest integration and ships as a Vite
plugin (`cloudflareTest()` in `vitest.config.ts`). Both peer-depend on vitest `^4.1`, so vitest 5 is not used yet.
The plugin bundles the same wrangler version as the project (4.131.2) and runs tests in Miniflare, so Durable Object,
KV, R2, Queue and Workflow bindings from `wrangler.jsonc` are real local bindings.

Two harness caveats observed with 1.1.9, both handled in `test/setup.ts` and `test/helpers.ts`:

- Storage is not isolated per test and `reset()` leaves SQLite-backed Durable Objects and KV untouched. Every test
  therefore gets its own client id (its own projection object), the budget object is emptied through
  `runInDurableObject`, and KV/R2 keys are deleted before each test.
- `getQueueResult()` reports retried message ids without `delaySeconds`; the retry delay schedule is asserted
  through the exported `retryDelaySeconds()` instead.

`worker-configuration.d.ts` is generated by `npm run types` (`wrangler types --env preview --strict-vars=false`)
and committed so editors work without a build step; `npm run typecheck` regenerates it first.

## Feature flags and vars

All flags default to `"false"` in both environments. A flag is on only when its value is exactly `"true"`.

| Var | Default | Effect |
| --- | --- | --- |
| `SUPERVISION_ENABLED` | `false` | Create `BuddyTaskSupervisor` instances and forward terminal events to them |
| `AUTO_RECOVERY_ENABLED` | `false` | Allow the supervisor to request one `recover_evaluation` for a transient failure |
| `READ_CACHE_ENABLED` | `false` | Use KV for artifact summaries after a metadata-only authorization read |
| `BROWSER_DIAGNOSTICS_ENABLED` | `false` | Enable `POST /internal/captures`; off returns `503 browser_diagnostics_disabled` |
| `AZURE_API_BASE` | `https://buddy.aerolambda.tech` | Azure origin for the internal contract |
| `ALLOWED_ORIGIN` | workers.dev placeholder | The only browser `Origin` accepted for session exchange and stream tickets |
| `DAILY_BUDGET_EVENTS` | `50000` | Daily cap for consumed events (terminal events keep an operating reserve) |
| `DAILY_BUDGET_CALLBACKS` | `500` | Daily cap for supervisor calls to Azure |
| `DAILY_BUDGET_WORKFLOWS` | `200` | Daily cap for supervisor instance creation |
| `DAILY_BUDGET_CAPTURES` | `10` | Daily cap for browser captures (plus at most 2 concurrent) |
| `MAX_ACTIVE_SOCKETS_PER_TASK` | `20` | Maximum open dashboards per task projection |

Budgets deny at 100% and log one warning per day and kind at 80%. Counters live in the `BuddyEdgeBudget`
Durable Object, never in KV.

| Secret | Set with | Purpose |
| --- | --- | --- |
| `EDGE_SERVICE_KEY` | `wrangler secret put EDGE_SERVICE_KEY --env preview` (and `--env production`) | Sent to Azure as `X-Buddy-Edge-Key`; required by Azure on `/internal/*` routes of this Worker |

## HTTP surface

| Route | Auth | Notes |
| --- | --- | --- |
| `POST /session/exchange` | Ticket in body, `Origin` must match `ALLOWED_ORIGIN` when present | Sets `buddy_view` (session token) and `buddy_scope` cookies: HttpOnly, Secure, SameSite=Strict, Path=/, Max-Age from `expires_at`. Body `{task_id, expires_at}` only |
| `GET /tasks/:task?after=N` | Session cookie | Fresh Azure snapshot, projection reconcile in the background, `{progress, events, observed_at}` |
| `POST /tasks/:task/stream-tickets` | Session cookie + `Origin` | Tail snapshot (`after_sequence=2147483647`) to re-authorize, then a single-use 60 s ticket |
| `GET /tasks/:task/events?ticket=` | Session cookie + ticket | WebSocket upgrade handled by the Durable Object (hibernation, 30 s ping, close `4001` five minutes after a terminal event) |
| `GET /tasks/:task/artifacts/:artifact/summary` | Session cookie | Origin or cache (`X-Buddy-Cache: origin|cache`) |
| `POST /internal/captures` | `X-Buddy-Edge-Key` | Browser diagnostics, gated by flag, policy, budget and concurrency |
| `GET /internal/budget` | `X-Buddy-Edge-Key` | Counter and reconciliation read |
| `POST /internal/events` | `X-Buddy-Edge-Key` | Body is one event envelope (not wrapped). `422 invalid_envelope`, `429 budget_exhausted` (terminal events always pass), `202 {queued, event_id}`. `buddy.task.artifact.*` goes to `BUDDY_ARTIFACT_EVENTS`, everything else to `BUDDY_EVENTS` |
| `PUT /uploads/:token` | `bup1` token | Streams the body into R2 under the token's key with its `content_type` and `upload_id` metadata. `413 upload_too_large` from `Content-Length` or once the counted stream passes `max_bytes`. `201 {key, size, etag}` |
| `GET /downloads/:token` | `bdl1` token | Streams the object with the token's `content_type` (never the stored one), `Content-Disposition: attachment; filename="<sanitized>"`, `Cache-Control: no-store`. `404 not_found` |
| `GET /internal/objects/meta?key=` | `X-Buddy-Edge-Key` | `200 {size, content_type, etag}` or `404` |
| `GET /internal/objects/content?key=` | `X-Buddy-Edge-Key` | Streams the bytes with the stored content type, `404` when missing |
| `POST /internal/objects/copy` | `X-Buddy-Edge-Key` | Body `{from, to}`; server-side copy keeping metadata, `200 {size}`, `404` when `from` is missing |
| `DELETE /internal/objects?key=` | `X-Buddy-Edge-Key` | Always `204` |
| everything else | – | Static assets (`public/`) |

Every object key on these routes must start with `clients/` (`400 key_invalid` otherwise). Azure holds no R2
credentials or Cloudflare API token: the Worker is the only writer, authenticated by `EDGE_SERVICE_KEY` alone.

### Signed object tokens

Azure mints tokens with the shared `EDGE_SERVICE_KEY`; the Worker verifies them with WebCrypto and a timing-safe
compare. Format (base64url, no padding): `<kind>.<base64url(json payload)>.<base64url(HMAC-SHA256(payload segment))>`.

| Kind | Payload | Used by |
| --- | --- | --- |
| `bup1` | `{key, max_bytes, content_type, exp, upload_id}` | `PUT /uploads/:token` |
| `bdl1` | `{key, filename, content_type, exp}` | `GET /downloads/:token` |

`exp` is unix seconds and a token is rejected when `exp <= now`. The HMAC covers only the payload segment, so a
relabelled token (`bup1` presented as `bdl1`) still verifies; the per-kind payload shape check rejects it. All
failures answer `401 {error: "token_invalid", reason}` and the token is never echoed in a response or a log line.
Chunked uploads (no `Content-Length`) are buffered up to `max_bytes` before the R2 put; uploads with a
`Content-Length` stream straight through.

Every response carries `Content-Security-Policy: default-src 'self'; connect-src 'self'; img-src 'self' data:; frame-ancestors 'none'; base-uri 'none'`,
`Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`; API routes add `Cache-Control: no-store`.

WebSocket protocol (JSON text frames): server sends `hello`, `event`, `snapshot`, `snapshot_required`, `resume_ok`, `ping`;
client sends `{type:"resume", after_sequence}` and `{type:"ping"|"pong"}`.

## Dashboard link format

`https://<worker-host>/#ticket=<view-ticket>` (or `/?task=<task_id>#<view-ticket>`). The page clears the fragment
immediately with `history.replaceState`, exchanges the ticket, and rewrites the URL to `/?task=<task_id>` so a
reload resumes from the cookie session. When WebSockets fail three times it shows a visible polling fallback
that uses `next_poll_after_ms`.

## Tests

`npm test` covers projection ordering/dedup/gap/reconcile and buffer bounds (100 events, 24 h), single-use and
expiring tickets, session exchange (cookies, Origin, no token echo), WebSocket resume and gap signalling,
consumer ack/retry semantics and DLQ path, supervisor creation idempotency and the not-eligible Workflow path,
the decision table, KV hit/miss/authorization-first/flag-off, capture policy rejections and the disabled flag,
the budget 80%/100% behaviour, token verification (including a known-answer vector produced with Node's `crypto`
and the relabelled-token case), event ingestion (auth, 422, 202, artifact routing, 429 and the terminal reserve),
uploads (both 413 paths, stored metadata), downloads (attachment headers, fixed content type, name sanitizing) and
the internal object API. Azure is stubbed by replacing global `fetch`; the queue producers are replaced by recorders
because this plugin version offers no producer-side inspection. Nothing reaches a real resource.

## Budget note

Events published through `POST /internal/events` are counted once at ingestion and
once again when the consumer applies them, so `DAILY_BUDGET_EVENTS` is consumed
at two units per event; 50,000 units is therefore 25,000 events per day, far
above the expected volume. Terminal events always pass.
